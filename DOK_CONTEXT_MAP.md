# Dokümantasyon bağlam haritası

- Ana route'lar: `/dokumantasyon`, `/dokumantasyon/dosya/[fileId]`, `/p/[token]`, `/giris`.
- Ana component'ler: `admin-shell.tsx`, `file-manager.tsx`, `drive-sidebar.tsx`, `drive-details-drawer.tsx`; ilgili modal/yükleme ve preview bileşenleri aynı `src/components/dokumantasyon/` ağacında.
- API route'ları: `src/app/api/dokumantasyon/` altındadır; auth, klasör, dosya, çöp kutusu, paylaşım, upload ve preview tüketicileri burada aranır.
- DB erişim helper'ları: `src/lib/dokumantasyon/db.ts`, `files.ts`, `folders.ts`, `trash.ts`, `shares.ts`, `auth.ts`, `file-access.ts`.
- Preview: `src/app/dokumantasyon/dosya/[fileId]/page.tsx`, `src/components/dokumantasyon/file-preview-shell.tsx`; PDF/Görsel/CAD studio yardımcıları `src/lib/dokumantasyon/studio/` altında.
- Testler: `scripts/check-dokumantasyon-*.mjs`, Playwright yapılandırması ve e2e testleri (varsa) hedeflenir.
- Dokunulmaması gereken çalışan alanlar: auth, Neon/veri erişimi, Vercel Blob upload, share, trash, search ve mevcut preview altyapısı; yalnızca Aşama 1 P0 onarımlarıyla doğrudan ilgili minimum değişiklik yapılır.
- Mevcut P0 hipotezleri: mobil sidebar state'i DOM'a bağlı olmayabilir; preview/new-tab semantiği çakışabilir; mutation'larda non-OK/partial-failure görünür olmayabilir; fetch non-OK stale UI bırakabilir; upload metadata webhook yarışı olabilir.
- Aşama 2 bağlamı: `dok-workspace.module.css`, mobil details sheet ve responsive explorer shell; geniş ekran sidebar/details, dar ekranda drawer/sheet kullanır.
- Aşama 3 bağlamı: aktif route `DocumentStudioShell` kullanır. PDF `studio/pdf/`, image `preview/image-viewer.tsx`, CAD `preview/{cad-viewer,aps-dwg-viewer}.tsx`; image fit/pan ve CAD WebGL fallback testlerle kapsanır.
- Aşama 4 bağlamı: `starred_at` (dosya/klasör) ve spam-korumalı `last_opened_at` kalıcı metadata alanlarıdır; `items/route.ts` koleksiyon/filtre sorgularını taşır. Bulk move mevcut mutation contract'ını item bazlı partial-failure ile kullanır. Klasör yükleme yalnız destekleyen tarayıcıda dinamik picker ile çalışır; relative path sanitize edilir, mevcut aynı-adlı klasör yeniden kullanılır ve hiyerarşi kurulurken hata olursa yeni boş klasörler ters sırayla soft-delete edilir. Queue item gerçek `File` referansını tutarak hata başına retry sunar. Minimal activity kayıtları yalnız upload/rename/move/trash/restore/share olayları için `activity.ts` ve `/api/dokumantasyon/activity` üzerinden tutulur.
- Aşama 5 bağlamı: Kalıcı yaşam döngüsü sözleşmesi `DOK_STORAGE_CONTRACT.md` dosyasındadır. Ortak kararlar `storage-lifecycle.ts`, tek kontrollü mutabakat `scripts/reconcile-dokumantasyon-storage.mjs` içindedir. Upload intent/finalize idempotenttir; silme Blob/disk başarısızsa metadata'yı korur. Haricî sağlayıcı yalnız UX gerekçeli olduğundan eklenmemiştir. Viewer'lar lazy yüklenir; File Manager seçim durumu `use-dok-selection.ts` ile ayrılmıştır.
- Aşama 6 bağlamı: `tests/document-studio/release.spec.ts` Chromium, mobile Chromium, WebKit ve mobile WebKit için auth/session/logout, yedi viewport overflow, console/network ve release screenshot gate'lerini kapsar. Isolated test output `NEXT_DIST_DIR` ile `.next-playwright*` altında tutulur. Mobil selection bar alttaki navigasyonun üstünde kalır; safe-area CSS module üzerinden uygulanır.
